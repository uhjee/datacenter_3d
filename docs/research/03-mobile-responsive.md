# 03. 휴대폰 · 태블릿 화면 조사 · 계획

> 목적: PC 화면은 그대로 두고, **휴대폰**에서도 3D 시뮬레이터를 보고 조작할 수 있게 한다. **태블릿**은 PC · 휴대폰과 다른 **현장 모드**로 만든다. 들고 다니며 3D 화면으로 장비를 찾아가는 용도다(§9 ~ §14).
> 작성일: 2026-11-03(태블릿 현장 모드 추가 같은 날). 표기 규칙: **[확인]** = 공식 문서 · 1차 자료 · 라이브러리 소스로 확인, **[일반]** = 여러 2차 자료에서 같은 내용, **[측정]** = 이 프로젝트에서 직접 잰 값, **[추정]** = 근거가 약해 실기기로 확인해야 함.

## 0. 기기별 역할

세 화면은 같은 데이터와 3D 장면을 쓰지만 **하는 일이 다르다**.

| | PC | 휴대폰 | 태블릿(현장 모드) |
|---|---|---|---|
| 쓰는 곳 | 책상 | 이동 중 · 회의 | **데이터센터 현장**(서버실 · 기계실 · UPS실) |
| 주 목적 | 학습 · 분석 · 시나리오 | 보기 · 학습(PC 기능을 좁은 화면에) | **장비 찾아가기** · 그 자리에서 정보 확인 |
| 첫 화면 | 건물 전체 · 좌우 패널 | 3D 전체 화면 + 바텀 시트 | **찾기**(검색 · QR) + 내 위치 |
| 카메라 | 자유 회전 | 자유 회전 | 위에서 본 평면 · **사람 눈높이** 시점, 내 위치 · 방향 기준 |
| 입력 | 마우스 · 키보드 | 한 손 엄지 | 두 손으로 잡고 **양쪽 엄지** |
| 계획 | 지금 화면 유지 | §1 ~ §8 | §9 ~ §14 |

## 1. 휴대폰 범위

- **대상:** 세로 휴대폰(폭 360 ~ 430px)이 기본이다. 가로 휴대폰(높이 500px 미만)도 같은 모바일 화면으로 다룬다.
- **태블릿**(폭 600px 이상 + 터치)은 휴대폰 규칙을 쓰지 않고 현장 모드(§9~)로 간다. 기존 `@media (max-width: 900px)` 규칙(좌우 패널을 겹쳐 띄우기)은 터치가 아닌 좁은 PC 창을 위해 남긴다.
- **원칙:** 기능은 PC와 같게 두고 **배치와 입력만** 바꾼다. PC 코드 경로는 건드리지 않는다. 휴대폰인지 판별하는 곳은 CSS 미디어쿼리와 훅 하나(`useDevice`)로 모은다.

판별 조건(안):

```css
@media (max-width: 599px), (max-height: 499px) and (pointer: coarse) { … }
```

- 폭 600px는 Material의 compact 창 크기 경계와 같다. 태블릿 세로(768px~)는 이 조건에 걸리지 않는다.
- 가로 휴대폰은 폭이 800px를 넘을 수 있어서 `높이 < 500 + 터치`로 따로 잡는다.
- `pointer: coarse`는 기본 입력 장치만 본다. 터치 노트북 같은 혼합 기기는 `any-pointer: coarse`로 터치 타깃만 키운다 [일반].

## 2. 휴대폰: 지금 화면 진단 (375 × 812에서 측정)

브라우저 크기를 375 × 812(휴대폰)로 맞추고 열어 본 결과다 [측정].

### 2.1 배치

| 위치 | 문제 |
|---|---|
| 상단 바 | 내용 폭 716px > 화면 375px. 학습 버튼과 **정보 패널 열기 · 닫기 버튼이 화면 밖**으로 밀려 누를 수 없다. 제목 '데이터센터 3D 시뮬레이터'가 세로로 한 글자씩 꺾인다. |
| 좌우 패널 | 처음부터 열린 채로 시작하고, 폭 85vw로 3D를 거의 다 가린다. 오른쪽 패널을 닫는 버튼이 화면 밖이라 **닫을 방법이 없다**. |
| 3D 위 막대 | 층 막대(세로 8칸)와 카메라 막대가 좌우 끝을 차지해 3D 가운데 폭이 220px 남짓이다. |
| PUE 카드 | [전체] 보기에서 아래쪽 폭 대부분(300px)을 덮는다. |
| 온도 보기 | 온도 카드(340 × 238)가 층 막대 · 카메라 막대와 겹친다. 높이 막대(left 408px)는 **화면 밖**이다. 급기 · 수치 카드가 칩 줄과 겹친다. |
| 하단 도면 | 2D 상면도가 336px(화면의 41%)를 차지해 3D는 428px만 남는다. 도면 툴바도 두 줄로 넘친다. |

### 2.2 입력

| 기능 | 데스크톱 방식 | 휴대폰에서 |
|---|---|---|
| 회전 · 이동 · 확대 | 드래그 · 우클릭 드래그 · 휠 | camera-controls 기본 터치(1손가락 회전 · 2손가락 핀치 확대 + 이동)로 **이미 동작**한다. |
| 회전 중심 옮기기 | `dblclick` | 터치에서는 `dblclick`이 나오지 않거나 확대 제스처와 겹친다 [추정]. 직접 만든 더블탭이 필요하다. |
| 장비 선택 | 클릭 | 랙 `onClick`에 이동 거리 검사가 없다. 회전하려고 끌다 손을 뗄 때 선택이 바뀔 수 있다(히트맵만 `e.delta <= 2` 검사). |
| 마우스 올리면 나오는 정보 | 3D 이름표 · 온도 탐침 · 2D 상면도 값 · 높이 막대 `data-tip` · 층 태그 `floor-tip` · `title` 91곳 | **hover가 없어 모두 안 보인다**. InfoTip(ⓘ 17곳)은 눌러서 고정하는 기능이 있어 그대로 쓸 수 있다. |
| 검색 | ⌘K | 단축키가 없으니 버튼만 쓴다. 입력칸 글자가 16px보다 작으면 iOS가 화면을 확대한다 [일반]. |

| 보기 | draw call | 삼각형 | geometry | 픽셀 비율 |
|---|---|---|---|---|
| 전체(층 벌려 보기) | 1,251 | 26.8만 | 1,222 | 2 |

## 3. 휴대폰: 조사 요약

### 3.1 화면 배치 패턴

- **3D 전체 화면 + 바텀 시트.** 3D 뷰어 예제(SceneView)는 장면을 화면 가득 두고 설정을 아래에서 올라오는 시트에 넣는다. 시트 상태는 화면 회전 · 다크 모드 전환에도 유지한다 [일반].
- **시트를 조금만 내밀어 두기(peek).** 손잡이와 요약 한 줄만 보이게 아래에 걸어 두고, 위로 끌면 절반 · 전체로 펼친다. 같은 컴포넌트가 데스크톱에서는 떠 있는 패널이 되는 구성도 흔하다(OutSystems iOS 스타일 시트) [일반].
- **시트가 3D를 막지 않게.** 일부 디자인 시스템의 시트는 늘 어두운 덮개를 깔아 뒤 화면을 막는다. 3D를 보면서 조작해야 하므로 **덮개 없는 시트**가 맞다 [일반].
- **제스처 충돌.** 시트를 끄는 손잡이에는 `touch-action: none`을 준다. 3D의 회전 · 핀치와 시트 끌기가 서로 먹지 않게 영역을 나눈다 [일반].

### 3.2 터치 제스처 관례

| 사례 | 제스처 |
|---|---|
| three.js OrbitControls | 1손가락 회전, 2손가락 벌리기 · 오므리기 = 확대, 2손가락 이동 = 이동 [확인]. 2손가락으로 끌면 확대와 이동이 함께 일어난다는 보고가 있다 [일반]. |
| camera-controls(우리가 쓰는 것) | `touches.one / two / three`로 바꿀 수 있다. 기본은 1손가락 회전, 2손가락 확대 + 이동, 3손가락 이동이다 [확인: node_modules 소스]. |
| Sketchfab | 물체를 더블탭하면 그쪽으로 다가가며 회전 중심이 된다. 빈 곳을 더블탭하면 전체로 물러난다 [확인]. |
| Autodesk Forma | 표면을 더블탭하면 그 지점으로 날아간다 [확인]. |
| Autodesk Platform Services 뷰어 | 도구가 더블탭 이벤트를 따로 받는다(`handleDoubleTap`) [확인]. |

→ 우리 앱도 **탭 = 선택, 더블탭 = 그 지점을 회전 중심으로, 길게 누르기 = hover 대신 정보 보기**로 정하면 관례와 맞는다.

### 3.3 터치 타깃 · 판별

- 최소 크기: Apple HIG 44 × 44pt, Material 48 × 48dp, WCAG 2.2 AA 24 × 24px(AAA 44px) [일반]. → 모바일 버튼은 **44px 이상**으로 한다(아이콘은 작게 두고 누르는 영역만 넓혀도 된다).
- `@media (hover: none)`이면 hover로만 보이는 정보를 다른 길로도 볼 수 있어야 한다. 기능을 hover 뒤에만 숨기지 않는다 [일반].

### 3.4 화면 높이 · 노치

- `100vh`는 주소창이 나타나고 사라질 때 맞지 않는다. 앱 껍데기에는 `100dvh`를 쓴다(iOS Safari 15.4+) [일반].
- `viewport-fit=cover` + `env(safe-area-inset-*)`로 노치 · 홈 표시줄 밑에 버튼이 깔리지 않게 한다. 화면 가장자리에 붙는 요소만 여백을 주면 된다 [일반].
- 앱 안 브라우저(카카오톡 · 인스타그램 등 WebView)는 주소창 동작이 달라 실기기로 확인해야 한다 [일반].

### 3.5 WebGL 성능 · 메모리

- **픽셀 비율 상한.** 휴대폰은 `devicePixelRatio`가 3인 경우가 많다. 그대로 그리면 픽셀이 9배다. 상한을 1.5 안팎으로 두는 것이 흔한 권장이다 [일반].
- **iOS 메모리.** 탭이 메모리를 넘으면 Safari가 오류 없이 페이지를 새로 고친다는 보고가 있다 [일반]. iOS 업데이트 뒤 context lost가 났을 때 `antialias: false` · `powerPreference: 'default'`로 고쳤다는 보고도 있다 [일반].
- **적응형 품질.** drei `PerformanceMonitor`는 프레임이 떨어지면 `onDecline`을 부른다. `AdaptiveDpr`과 함께 쓰면 픽셀 비율을 자동으로 낮춘다 [일반].
- **HTML 이름표.** drei `<Html>`이 많으면 iPhone에서 프레임이 크게 떨어진다는 보고가 있다. 원인으로 raycast 가림 계산이 꼽힌다 [일반]. 우리 앱은 이름표를 대부분 `LabelOverlay` 한 곳에서 투영하고, drei `<Html>`은 층 태그 · 케이지 이름표에만 쓴다. 지금 수준이면 문제는 작을 것이다 [추정].

## 4. 휴대폰: 화면 구성안

### 4.1 기본 화면

```
┌──────────────────────────────┐
│ ☰  데이터센터 3D    🔍  🌡  ⋯ │  상단 바 48px (+ 노치 여백)
├──────────────────────────────┤
│ 전체│                   ⌂    │  층 막대(왼쪽, 칸 높이 40px)
│ PH  │                   ⛶    │  카메라 막대(오른쪽: 홈 · 맞춤 · ⋯ 메뉴)
│ 5F  │                        │
│ 4F  │        3D              │
│ 3F  │                        │
│ 2F  │                        │
│ 1F  │                        │
│ B1  │                        │
│         [칩 줄: 4F ✕ · 추적 ✕] │
├──────────────────────────────┤
│ ── (손잡이)                   │  바텀 시트 peek 72px
│ 건물 개요 · PUE 1.40          │  선택한 대상의 이름 · 핵심 수치 1줄
└──────────────────────────────┘
```

- **상단 바:** ☰(탐색 · 표시 서랍) · 짧은 제목 · 검색 아이콘 · [온도] 토글 · ⋯ 메뉴(도면 · 시나리오 · 가이드 투어). 오른쪽 패널 버튼은 없앤다(시트가 대신한다).
- **왼쪽 패널(탐색 · 표시):** 지금처럼 왼쪽에서 밀려 나오는 서랍으로 쓴다. 휴대폰에서는 처음에 닫아 둔다. 장비를 고르면 서랍을 자동으로 닫는다.
- **오른쪽 패널 → 바텀 시트:** 탭(정보 · 지표 · 주의 · 시나리오)은 그대로 두고 아래에서 올라오게 한다. 높이는 세 단계다.
  - 닫힘(peek 72px): 선택 대상 이름 + 핵심 수치 1줄. 고른 것이 없으면 PUE.
  - 절반(50dvh): 3D와 정보를 함께 본다. 기본으로 여는 높이다.
  - 전체(약 90dvh): 긴 표 · 시나리오 사건 기록.
- **층 막대:** 세로 그대로 두고 칸만 줄인다. 펼쳐 보기 · 겹쳐 보기 두 칸은 카메라 막대 ⋯ 메뉴로 옮긴다.
- **카메라 막대:** 홈 · 화면 맞춤만 보이고, 링크 복사 · 확대 · 축소 · 조작 안내는 ⋯ 안으로 넣는다(핀치로 확대할 수 있으므로).
- **PUE 카드:** 3D 위에 띄우지 않고 시트 peek 줄에 숫자만 보인다.
- **칩 줄 · 토스트 · 추적 배너:** 시트 바로 위에 쌓는다. 칩 줄은 가로로 넘기게 한다.

### 4.2 장비를 골랐을 때

1. 3D에서 랙 · 장비를 탭한다.
2. 시트 peek가 '이름 · 상태 · 핵심 수치'로 바뀐다(펼치지 않는다. 3D를 가리지 않으려고).
3. 위로 끌거나 peek를 탭하면 절반 높이로 열려 정보 카드 전체가 보인다.
4. 카메라가 그 장비로 움직일 때는 시트가 덮는 높이만큼 **화면 가운데를 위로 올려** 장비가 가려지지 않게 한다(camera-controls `setFocalOffset` 또는 화면 오프셋).

### 4.3 온도 보기

```
┌──────────────────────────────┐
│ ☰  데이터센터 3D    🔍  🌡• ⋯ │
├──────────────────────────────┤
│ 서버실 A · 3F   [상|중|하]    │  한 줄 머리: 서버실 이름 · 높이 세그먼트
│ ▁▂▃▅▇ 15 18 ─ 27 32 40       │  온도 바(권장 띠 포함)만 얇게
│                               │
│        3D 히트맵              │
│                               │
├──────────────────────────────┤
│ ── 온도 · 최고 흡기 20.7°C ✓  │  시트 peek
│ [온도] [급기 · 수치] [2D 상면도]│  시트 탭(온도 보기 중에만)
└──────────────────────────────┘
```

- 온도 카드에서 3D 위에는 **서버실 이름 · 높이 세그먼트 · 온도 바**만 남긴다. 히트맵 · 에어 플로우 태그, 시점 아이콘, 공조 조건, ⚙ 옵션은 시트의 [온도] 탭으로 옮긴다.
- 높이 [상 · 중 · 하]는 세로 막대 대신 가로 세그먼트로 둔다. hover 설명이 없으므로 길게 누르면 '1.9m 온도계 기준' 설명을 토스트로 띄운다.
- 급기 · 수치 카드는 시트의 [급기 · 수치] 탭으로 옮긴다.
- **2D 상면도는 아래쪽에 나눠 띄우지 않는다.** 시트 탭에서 전체 높이로 보거나, 3D ↔ 2D를 전환하는 방식으로 한다. 휴대폰 높이에서 둘을 함께 보면 둘 다 너무 작다.
- 온도 탐침: hover가 없으므로 히트맵을 **탭하면 그 자리 온도를 고정해서 보여 주고**, 다시 탭하면 지운다.

### 4.4 하단 도면(단선도 · 공조 흐름도)

- 휴대폰에서는 3D와 나눠 보지 않고 **전체 화면 도면 보기**로 연다. 2손가락 확대 · 1손가락 이동을 쓴다.
- 도면에서 장비를 탭하면 시트 peek에 정보가 나오고, '3D에서 보기'를 누르면 3D로 돌아가 그 장비로 이동한다.

### 4.5 가이드 투어 · 시나리오 · 검색

- **가이드 투어:** 왼쪽 패널 카드(폭 380px)를 바텀 시트 절반 높이로 옮긴다. 이전 · 다음은 시트 아래쪽 엄지 영역에 두고, 장 탭 · 단계 목록은 접는다. 3D는 위쪽 절반에서 투어 카메라 이동을 보여 준다.
- **시나리오:** 재생 막대(재생 · 속도 · 타임라인)는 시트 peek 자리에 고정한다. 사건 기록 · 조건은 시트를 펼쳐서 본다. `ScenarioClock`은 상단 바 아래 작은 띠로 둔다.
- **검색:** 전체 화면 모달로 열고, 입력칸 글자 16px 이상(iOS 자동 확대 방지), 결과 줄 높이 44px 이상으로 한다.

- 모바일 버튼 · 탭 · 토글은 누르는 영역을 44px 이상으로 한다(`pointer: coarse`에서만).

## 9. 태블릿 현장 모드: 범위

- **대상 기기:** iPad(10.9 ~ 13인치) · 갤럭시 탭 등, 짧은 변 600px 이상 + 터치. 가로가 기본이고 세로도 지원한다.
- **용도:** 현장 작업자가 태블릿을 들고 다니며 **목적지 장비 · 랙을 3D에서 확인하고 길 안내를 따라 찾아간다**. 도착하면 그 자리에서 랙 정보(흡기 온도 · rPDU A/B · 고객사 · 연결)를 본다.
- **기기가 아니라 '모드':** 태블릿에서는 현장 모드로 시작하고, 상단 [학습 모드]로 바꾸면 PC 화면(터치 크기만 키움)을 쓴다. PC에서도 주소에 `?mode=field`를 붙이면 현장 모드를 열어 시험할 수 있다.
- **판별(안):** `(pointer: coarse) and (min-width: 600px) and (min-height: 600px)`. iPad Safari는 기본으로 Mac처럼 자신을 알리므로 `navigator.maxTouchPoints > 1`로 보완한다 [일반].
- **전제:** 길 안내는 3D 배치가 실제 건물과 같아야 쓸모가 있다. 지금 데이터는 교육용 가상 건물이므로 이 건물 기준으로 만들어 시연하고, 실제 현장에 쓰려면 배치 데이터를 바꿔야 한다(§14 정할 것).

### 11.2 웹 기술 확인

| 기능 | 내용 |

## 12. 현장 모드 화면 구성안

### 12.1 가로(기본)

```
┌───────────────────────────────────────────────────────────────┐
│ ◉ 현장   🔍 장비 · 랙 찾기            [라벨 인쇄]  [학습 모드] │  상단 56px
├─────────────────────────────────────────┬─────────────────────┤
│                                         │ 목적지  랙 A-3-07    │
│   3D (평면 ↔ 눈높이)                     │ 3F 서버실 A · 3열 7번│
│                                         │──────────────────── │
│     ● 내 위치 (보는 방향 화살표)          │ ① 코어 → 3F          │
│     ┅┅┅ 바닥 경로 선                      │ ② 서버실 A 출입문     │
│     ◎ 목적지 (깜빡임)                     │ ③ 3열 냉복도로 ◀ 지금 │
│                                         │ ④ 왼쪽 7번째 랙      │
├─────────────────────────────────────────┤──────────────────── │
│ [B1 1F 2F 3F 4F 5F PH] [평면|눈높이] [⌖] │  [이전]    [다음]    │
└─────────────────────────────────────────┴─────────────────────┘
  ← 왼쪽 엄지: 층 · 시점 · 내 위치               오른쪽 엄지: 단계 →
```

- 3D가 약 70%, 오른쪽에 **길 안내 패널**(폭 340px)을 고정한다.
- 두 손으로 잡는 것을 기준으로 **엄지가 닿는 아래쪽 양 모서리**에 자주 쓰는 버튼을 둔다. 왼쪽은 층 · 시점 · 내 위치, 오른쪽은 이전 · 다음 · 도착이다. 걸으면서 누르므로 버튼은 **56px**로 한다(44px 기준보다 크게).
- 글자는 본문 16px 이상으로 하고 대비를 높인다. 냉복도는 밝고 열복도는 어둡기 때문이다 [추정].
- **세로:** 위 3D 60%, 아래 길 안내 패널 40%. 엄지 버튼은 패널 아래쪽에 모은다.

### 12.2 쓰는 흐름

1. **목적지 정하기:** 검색(장비 · 랙 · 고객사 케이지), [주의] 목록(흡기 초과 랙 · 회로 여유 부족 등), 다른 사람이 보낸 링크.
2. **내 위치 정하기:** QR 라벨 찍기(층 코어 · 실 출입문 · 열 끝. 지금은 3D 속 QR 표지를 탭). 또는 손으로 층 → 실 → 열을 고른다. 아무것도 없으면 '코어(계단 · 승강기)에서 출발'로 본다.
3. **경로 보기:** 3D 바닥에 경로 선, 오른쪽에 단계 목록. 층이 다르면 '코어로 → n층'이 첫 단계다.
4. **걸으며 넘기기:** 사람이 실제로 걸어가면서 [다음]을 누르거나 가는 길의 QR을 찍으면 내 위치가 바뀐다. 자동 측위는 하지 않는다. 화면 속 내 위치 표시는 다음 지점으로 바로 옮겨지며, **걷는 동작을 흉내 내는 애니메이션은 만들지 않는다**(2026-11-03 결정).
5. **도착:** 카메라가 랙 앞 눈높이로 가고 랙을 강조한다. 정보 카드(흡기 온도 · rPDU A/B · 고객사 · 연결)가 나온다.
6. **이어 가기:** '이 랙 전원 따라가기'를 누르면 상류 PDU · UPS가 다음 목적지가 된다. 기존 상류 추적을 그대로 쓴다.

### 12.3 시점

- **평면(기본):** 지금 층만 위에서 본다. 다른 층은 숨기고 내 위치를 화면 가운데에 둔다.
- **눈높이:** 카메라를 바닥 위 1.6m에 두고 통로 방향을 본다. 위치는 고정하고 1손가락으로 좌우를 둘러본다. 다른 곳으로 가려면 [다음]을 누르거나 평면에서 탭한다.
- **보는 방향 맞추기:** 기기 나침반(DeviceOrientation)은 iOS에서 권한 요청이 필요하다. 실내 랙 · 전원 설비 옆에서는 자기장이 흔들려 믿기 어렵다 [추정]. 그래서 **QR 라벨에 '라벨을 보고 섰을 때의 방향'을 넣어** 찍는 순간 방향을 맞추고, 손으로 돌려 바로잡게 한다.

### 12.4 QR 라벨 체계(안)

| 붙일 곳 | 주소 예 | 찍으면 |
|---|---|---|
| 층 코어(승강기 앞) | `…/#here=core:3F&face=S` | 내 위치 = 3F 코어, 남쪽을 보고 섬 |
| 실 출입문 | `…/#here=door:3F-A&face=E` | 내 위치 = 서버실 A 문 앞 |
| 열 끝(냉복도 쪽) | `…/#here=row:A-3&end=W` | 내 위치 = 3열 서쪽 끝 |
| 랙 문(선택) | `…/#here=rack:A-3-07` | 내 위치 = 그 랙 앞, 정보 카드 열기 |

- **위치 입력은 한 곳으로 모은다.** 손으로 고르기 · 주소 링크 · 3D 속 QR 표지 모두 같은 함수(`setHere(장소, 방향)`)를 부른다. 실제 라벨이 생겨도 앱 쪽 코드는 바뀌지 않는다.
- **실제 라벨:** 기기 카메라 앱으로 찍으면 링크로 앱이 열리고 위치가 바뀐다. 링크를 여는 것뿐이라 HTTPS · 스캐너 라이브러리가 필요 없다.
- **지금(가상 건물) 시연:** 붙일 자리(코어 앞 · 실 출입문 · 열 끝)에 작은 **QR 표지를 3D로** 둔다. 표지를 탭하면 '찍었다'로 처리해 실제 라벨과 같은 `setHere`를 부르고 주소 해시를 바꾼다.
- **라벨 인쇄 페이지:** 장소 목록에서 QR을 A4로 뽑는다. 사무실에서 종이 · 모니터의 QR을 태블릿 카메라로 찍어 실제 흐름을 확인할 수 있다.
- **앱 안 카메라 스캐너는 만들지 않는다.** HTTPS와 WASM 라이브러리가 필요하고, 실제 라벨이 붙기 전에는 쓸 데가 없다. 실제 현장에 적용할 때 다시 정한다.

## 15. 구현 순서 (단계별 계획)

### 15.1 전체 순서

```
공통   S1 기기 판별 · 화면 틀 ─▶ S2 터치 입력 ─▶ S3 렌더링 품질
                                        │
              ┌─────────────────────────┴─────────────────────────┐
휴대폰        S4 상단 바 ─▶ S5 바텀 시트 ─▶ S6 3D 위 막대 ─▶ S7 온도 보기 ─▶ S8 도면 · 투어 · 시나리오 · 검색
태블릿        S9 현장 모드 틀 ─▶ S10 위치 데이터 · 경로 ─▶ S11 길 안내 ─▶ S12 내 위치 · QR ─▶ S13 현장 편의
              └─────────────────────────┬─────────────────────────┘
마무리                           S14 실기기 확인
```

- **공통(S1 ~ S3)** 을 먼저 한다. 휴대폰과 태블릿이 둘 다 쓰는 판별 · 화면 높이 · 터치 입력 · 렌더링 품질이다.
- 그 뒤 **휴대폰(S4 ~ S8)** 과 **태블릿(S9 ~ S13)** 은 서로 기대지 않으므로 어느 쪽을 먼저 해도 된다. 제안은 태블릿 먼저다. 현장 모드가 새로 생기는 기능이고, 휴대폰은 기존 화면 재배치라 나중에 해도 위험이 작다.
- 단계마다 빌드가 통과하면 커밋 · 푸시한다. 한 단계가 크면(S5 · S11) 나눠서 커밋한다.
- 단계마다 PC 화면(1280 · 1440 폭)이 그대로인지 스크린샷으로 확인한다.

규모는 대략 **작음**(파일 1~3개, 반나절), **중간**(파일 4~8개, 하루), **큼**(새 구조 · 데이터, 이틀 이상)으로 적었다.

### 15.3 휴대폰 (§4 ~ §5)

#### S4 상단 바 · ⋯ 메뉴 — 작음

- 상단 바: ☰ · 짧은 제목 · 검색 아이콘 · [온도] · ⋯. ⋯ 안에 도면 · 시나리오 · 가이드 투어. 오른쪽 패널 버튼은 숨김.

- **확인:** 375px에서 상단 바 내용 폭 ≤ 화면 폭, 모든 버튼을 누를 수 있음.

#### S5 바텀 시트 — 큼 (나눠서 커밋)

1. 시트 부품: 손잡이 끌기 · 3단계 높이(peek 72px · 50dvh · 90dvh) · 덮개 없음 · 안쪽 스크롤 `overscroll-behavior: contain`. `src/ui/Sheet.tsx`(새 파일)
2. 오른쪽 패널 내용을 휴대폰에서는 시트에 담기: 탭(정보 · 지표 · 주의 · 시나리오)은 그대로. `src/App.tsx`, `src/ui/InfoPanel.tsx`
3. peek 요약 줄: 선택 대상 이름 · 상태 · 핵심 수치 1줄, 없으면 PUE. `src/ui/SheetPeek.tsx`(새 파일)

#### S6 3D 위 막대 정리 — 중간

- 층 막대 칸 축소, 펼치기 · 겹치기는 카메라 ⋯로. 카메라 막대는 홈 · 맞춤 · ⋯만. `src/ui/ViewControls.tsx`

- 카메라 이동 시 시트가 덮는 만큼 화면 가운데를 위로(`setFocalOffset`). `src/scene/focus.ts`

**확인:** 기본 화면에서 3D 가운데 폭 280px 이상. 장비로 이동했을 때 장비가 시트에 가려지지 않음.

#### S7 온도 보기 — 중간

- 3D 위에는 서버실 이름 · 높이 세그먼트 · 온도 바만. 나머지(표시 태그 · 시점 · 공조 조건 · ⚙)는 시트 [온도] 탭으로. `src/ui/ThermalPanel.tsx`

**확인:** 온도 보기의 모든 조절(히트맵 · 에어 플로우 · 높이 · 시점 · 공조 조건 · 급기)을 휴대폰에서 할 수 있음.

### 15.4 태블릿 현장 모드 (§9 ~ §13)

#### S9 현장 모드 틀 — 중간

- `mode === 'field'`이면 다른 화면 틀: 상단 바(찾기 · [학습 모드]), 3D, 오른쪽 길 안내 패널(가로) 또는 아래 패널(세로), 엄지 버튼 줄. `src/ui/field/FieldLayout.tsx`, `FieldPanel.tsx`, `ThumbBar.tsx`(새 폴더), `src/App.tsx`
- 3D는 층 하나만 보이게(기존 `floorFocus` 사용).
- 길 안내가 없을 때 패널은 '찾을 장비 · 랙을 고르세요' + 검색 · [주의] 목록 바로가기.

**확인:** 1024 × 768 · 1180 × 820(가로), 820 × 1180(세로)에서 3D가 60% 이상, 엄지 버튼 56px이 아래 양 모서리에 있음. [학습 모드]로 바꾸면 지금 PC 화면.

#### S10 위치 데이터 · 경로 — 큼

| 작업 | 파일 |
|---|---|
| 장소(Place) 데이터: 층별 코어 도착점, 실 출입문(좌표 · 방향), 열 끝(냉복도 쪽 양 끝), 랙 앞 | `src/data/places.ts` (새 파일) |
| 출입문 좌표: 지금 `ROOMS`의 사각형에 문 자리를 손으로 적는다(실 20여 개 중 경로에 필요한 실부터) | `src/data/places.ts` |
| 경로망: 복도(`kind: 'corridor'` 실) · 전실의 꺾이는 점을 잇고, 서버실 안 통로는 랙 열 배치로 자동 생성. 층 사이는 코어로 잇는다 | `src/data/navGraph.ts` (새 파일) |
| 최단 경로(다익스트라) + 단계 문구 만들기('코어로 → 3F', '서버실 A 출입문', '3열 냉복도로', '왼쪽 7번째 랙') | `src/data/route.ts` (새 파일) |
| 개발용 점검: 모든 랙 · 장비가 모든 층 코어에서 닿는지 콘솔에서 확인(`__route`) | `src/data/route.ts` |

**확인:** 점검 함수로 전체 장소 쌍이 이어짐. 몇 경로는 2D 상면도에 선을 그려 눈으로 확인.

#### S11 길 안내 — 큼 (나눠서 커밋)

1. 상태: `here`(장소 · 방향) · `route`(목적지 · 단계 · 지금 단계)를 저장소에. 단계가 넘어가면 `here`를 그 단계 끝 지점으로 바로 옮긴다(걷기 애니메이션 없음). `src/store/useView.ts`
2. 목적지 고르기: 검색 결과 · [주의] 항목 · 정보 카드에 '여기로 길 안내'. `src/ui/SearchPalette.tsx`, `AlertPanel.tsx`, `InfoPanel.tsx`
3. 3D 표시: 바닥 경로 점선, 내 위치(보는 방향 화살표), 목적지 고리. `src/scene/RouteLine.tsx`(새 파일)
4. 시점: 평면(층 하나 위에서, 내 위치 가운데) · 눈높이(바닥 위 1.6m, 위치 고정 · 둘러보기만: 이동 · 확대 끔). `src/scene/focus.ts`, `Scene.tsx`(CameraRig 설정 전환)
5. 길 안내 패널: 목적지 · 단계 목록 · 지금 단계 강조 · [이전] [다음]. `src/ui/field/FieldPanel.tsx`
6. 도착: 랙 앞 눈높이로 이동, 랙 강조, 정보 카드. '이 랙 전원 따라가기' → 상류 추적 결과의 다음 장비를 새 목적지로. `src/ui/field/Arrival.tsx`(새 파일), 기존 추적(`startTrace`) 사용

**확인:** 3F 코어에서 랙 하나, 다른 층 UPS 하나까지 [다음]만으로 끝까지 안내. 눈높이에서 1손가락으로 둘러보기만 되고 위치가 움직이지 않음.

#### S12 내 위치 · QR — 중간

| 작업 | 파일 |
|---|---|
| 위치 입력 한 곳: `setHere(장소, 방향)` | `src/store/useView.ts` |
| 주소 해시 `#here=…&face=…` 읽기 · 쓰기(QR 라벨 · 공유 링크) | `src/store/persist.ts` |
| 손으로 위치 고르기: 층 → 실 → 열 목록 | `src/ui/field/PickHere.tsx` (새 파일) |
| 3D 속 QR 표지: 코어 앞 · 실 출입문 · 열 끝에 작은 표지. 탭하면 `setHere` + 해시 갱신 + '찍었습니다' 토스트 | `src/scene/QrMarks.tsx` (새 파일) |
| 라벨 인쇄 페이지: 장소별 QR + 이름 · 붙일 곳을 A4 격자로. QR 그림 생성 라이브러리 하나 추가(예: `qrcode`) | `src/ui/field/LabelSheet.tsx` (새 파일), `package.json` |

**확인:** 3D 표지를 탭하면 내 위치 · 방향이 바뀌고 경로가 다시 계산됨. 인쇄 페이지의 QR을 휴대폰 카메라로 찍으면 같은 주소가 열림(개발 서버 Network 주소 기준).

#### S13 현장 편의 — 중간

- 화면 꺼짐 방지: 길 안내 중에만 Wake Lock, 지원하지 않으면 건너뜀. `src/ui/field/useWakeLock.ts`(새 파일)
- 오프라인: `vite-plugin-pwa`로 서비스 워커 · 매니페스트 · 아이콘. `vite.config.ts`, `package.json`, `public/`
- HTTPS 개발 서버: `@vitejs/plugin-basic-ssl`을 `npm run dev:https` 같은 별도 명령으로(평소 개발은 그대로 http). `vite.config.ts`, `package.json`
- 현장 화면 글자 크기 · 대비: 현장 모드 전용 CSS 변수. `src/styles.css`

**확인:** HTTPS로 연 태블릿에서 길 안내 중 화면이 꺼지지 않음. 한 번 연 뒤 비행기 모드에서 새로 고쳐도 열림.

### 15.5 마무리

#### S14 실기기 확인 — 중간

- 기기: iPhone Safari, Android Chrome, iPad Safari, 갤럭시 탭 Chrome.
- 잴 것: 회전 중 프레임(목표 30fps 이상), 10분 사용 중 새로 고침 없음, 시트 · 엄지 버튼 손 닿음, QR 라벨(인쇄 페이지) 찍기.
- 결과에 따라 정하기: 휴대폰 첫 화면(§8), draw call 줄이기(§6), 가로 휴대폰 지원(§8).
- 결과는 이 문서 §2 · §10에 [측정]으로 덧붙인다.

### 15.6 단계별 결정 · 확인 방법 요약

| 단계 | 끝나면 할 수 있는 것 |
|---|---|
| S1 ~ S3 | 휴대폰 · 태블릿에서 화면이 넘치지 않고, 터치로 탭 · 더블탭 · 길게 누르기가 맞게 동작 |
| S4 ~ S8 | 휴대폰만으로 PC의 모든 기능(장비 정보 · 추적 · 온도 · 도면 · 투어 · 시나리오)을 씀 |
| S9 ~ S11 | 태블릿에서 목적지를 고르면 코어부터 랙 앞까지 단계별로 안내 |
| S12 | 3D 표지 · 인쇄 라벨 · 링크로 내 위치를 알림 |
| S13 | 현장에서 화면이 꺼지지 않고, 통신이 끊겨도 열림 |
| S14 | 실기기 숫자로 남은 결정(첫 화면 · 성능)을 마무리 |
